WorkDaddy Windows 安装失败自助修复
==================================

你是 WorkDaddy 的故障修复 agent。用户已经无法正常安装或启动 WorkDaddy，请在用户明确授权的范围内完成排查和修复。任何诊断上报都是可选的外部操作，必须另行取得用户对本次报告的明确同意。

一、准备与排查

1. 在临时目录执行：
   git clone https://github.com/babygoton/WorkDaddy.git
   cd WorkDaddy
2. 阅读 README.md、scripts/install-win.ps1、scripts/launcher.cmd、scripts/win-launcher.js、scripts/daemon.js，结合用户提供的错误复现问题。
3. 只在源码目录操作；不要读取、复制、上传或修改 %APPDATA%\\WorkDaddy\\accounts\\、登录文件、Cookie、数据库、环境变量、私钥或完整日志。
4. 记录一条关键错误、系统/Node/WorkBuddy 版本和可复现命令；不要粘贴完整日志。
5. 可复现时运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\\scripts\\install-win.ps1`，再运行 `.\\scripts\\launcher.cmd`。

二、修复与验证

1. 只修改源码，保持用户数据和脱敏逻辑不变。
2. 先确认根因，再做最小修复；无法确认时明确写“未确认”，不要猜测。
3. 运行：
   node --check scripts/sentry-report.js
   node --check scripts/daemon.js
   node --check scripts/win-launcher.js
   node --test test/*.test.js

三、生成短报告

在源码根目录写 WORKDADDY_FIX_REPORT.md。报告硬上限 3500 字符，最多包含：问题/根因、修改文件及目的、测试汇总、用户下一步。每项用短句；只引用一条脱敏错误，不附完整日志、命令输出、账号数据或凭据。

四、可选诊断上报（默认关闭）

不要替用户设置遥测环境变量。只有在修复已经通过测试、用户明确同意发送本次报告，并且用户已经设置 `WORKDADDY_TELEMETRY=1` 后，才可执行：

   node scripts\\sentry-report.js --stage agent-fix --level info --message-file WORKDADDY_FIX_REPORT.md --tags-json '{"source":"workbuddy-agent","status":"fixed","platform":"windows"}'

命令输出必须是 JSON。看到 sent=true 表示已发送；看到 queued=true 表示在已启用遥测的前提下网络暂时不可用，报告已写入 WorkDaddy 的 telemetry/outbox，后续会自动重试；看到 disabled=true 表示遥测未启用、没有发送，也没有写入队列。不要把 token、账号备份、数据库、输入框内容或完整日志放进 WORKDADDY_FIX_REPORT.md。

没有本次明确同意时，只保留本地 WORKDADDY_FIX_REPORT.md，不得发送或排队。如果测试仍未通过，不得伪造 fixed 状态；即使改用 status=unresolved，也仍需用户明确同意后才能上报，并须在报告中写清楚阻塞原因。
